What has been built

Committed work, 9–20 July 2026. All of this is real and in main.

Learning & assessment

  • Scored, gated quizzes — a lesson only completes at ≥ 70%, enforced in interactive_quiz_section.dart
  • Grading for multiple-choice, true/false, dictation and free-text answers (case- and space-normalised)
  • Single-skill lesson separation — a listening lesson renders only listening, no cross-skill bleed
  • Audio player with asset-existence fallback, so a missing file degrades instead of crashing
  • Roadmap, per-skill paths, unlock gating, placement test, level tracks

Evidence & the certificate loop

  • Students record speaking submissions in-app (web + native, record package)
  • Students hand in writing typed or as a photographed page
  • Teacher review queue — listen, read, approve or request a redo
  • Four-skill scoring with a 70% independent threshold per skill
  • Teacher certificate sign-off screen
  • Certificate issuing with a public human-readable code (TSL-A1-…)

Backend

  • Live Supabase project tasilla project, healthy, Postgres 17 — 7 tables, RLS on all
  • Student login derives real Supabase credentials from an access code, so auth.uid() is populated and RLS actually applies
  • A DB check constraint (four_skill_minimum) makes a sub-standard certificate row physically impossible
  • A trigger stops a student writing their own approved status — self-certification is blocked at the database, not just the UI
  • Anon-readable policy on non-revoked certificates, which is what makes public verification possible

The latest changes

Everything below post-dates the last commit and lives only in the working tree. 10 files modified, 9 added, 79 deleted.

1 — The course content was completely replaced

The 2,972-line generated Dart seed (a1_learning_experience_data.dart) has been swapped for 149 authored JSON files in assets/content/a1/, loaded at boot through a new a1_content_loader.dart and a generated manifest. All seven consumers were rewired; ID parsing gained a TASILLA branch (A1-T01-VOC) with the legacy A1-EXP-001 scheme kept as a fallback.

This is genuinely good content: real speaking rubrics with four scored criteria, per-question explanations, phrase banks, embedded grammar. And it quietly completes most of Phase 3 of the roadmap, which was scheduled for v1.2. The counts in level_track_data.dart were updated to match the new content exactly.

2 — The public verification page was built

verify_certificate_screen.dart (472 lines) plus hash-based routing in main.dart, so #/verify/TSL-A1-XXXXX resolves with no login and no server rewrites — deliberately chosen to survive GitHub Pages. It shows level, scores, issuing teacher and the proven can-do statements. This was the roadmap's single named Phase 0 blocker.

3 — Student home screen rebuilt

Skill cards went from a fixed 1.5-ratio grid to a responsive layout that collapses to one column under 700px. Each card now shows a four-step window anchored on the student's current step, with lock/current/done states, and the current lesson opens directly from the card.

4 — Schema documentation verified against production

docs/supabase_schema.md was rewritten from a 5-table description to the real 7-table state, with 33 RLS policies, storage bucket policies and the review-authority trigger all documented as verified live on 17 July.

5 — Two new specs, nothing built

docsv2/ adds a gamification spec (streaks, XP, map-based leagues, pets) and a teacher fidelity spec (tiers, public teacher pages, content feedback loop). Both are explicitly marked as documented-for-later.

✓ RESOLVED: all 40 audio files generatedResolved

40 of 40 content references now resolve. 13.2 MB in assets/audio/a1/, generated from the authored scripts via generate_a1_audio.py.

Cast, after the stock ElevenLabs voices were rejected for sounding like generic AI narration:

  • Nichalia — narrator, carries 12 of the 16 monologues
  • Brian — male dialogue
  • Alice — second female; the exam needs Zara and Woman tellable apart
  • Robert — spare

Five defects in the first version of the generator were found and fixed before the full run, all of which would have shipped silently:

  • Stage directions read aloud — a voice would have announced "SCENE ONE MONOLOGUE" inside the final exam
  • Exam voices inverted — voices were assigned by order of appearance, so Zara was male and the Man was female, contradicting every gendered question in the exam
  • Four male narrators voiced female — T03, R1, R6, CP2; R1 asks "How does he spell his name?"
  • Every 2-speaker dialogue got 3 voices — wrapped lines were parsed as a new person
  • The final test is two separate recordings, not one — Part B's eleven questions carry their own audioPath and had no audio

Delivery settings were also wrong: stability was 0.70, which is the high-consistency end and reads as monotone. Now 0.40 with style 0.30, and each dialogue turn is rendered with previous_text/next_text so intonation carries across the conversation.

RemainingListen to finalexam_listening.mp3 and t03_listening_my_family.mp3 to confirm casting in context. The 28 orphaned a1_exp_*.mp3 files from the old content scheme are now unreferenced and can be removed in their own commit.
The content generator is not in the repoCritical

Both a1_content_loader.dart and the manifest header name tools/convert_tasilla_content.py as the generator for all 149 JSON files. There is no tools/ directory, and the script exists nowhere in the project. The old tool/ directory was deleted too.

The manifest is marked "GENERATED — do not edit by hand", so the course content is currently unregenerable and only hand-editable against that instruction.

FixRecover the script and commit it alongside the JSON, or delete the generated-file headers and accept the JSON as hand-authored source.
All 14 tests were deletedCritical

The entire test/ directory is gone from disk, including certificate_service_test.dart, certificate_evidence_test.dart, learning_step_score_gate_test.dart and submission_service_test.dart.

The timing is the problem: coverage vanished in the same working tree where the content foundation underneath the certificate gate was swapped. The tests that would have caught the scope change below are exactly the ones removed.

Fixgit checkout -- test/, then run them. Expect real failures — several assert against A1-EXP- IDs that no longer exist. Those failures are the audit.
The certificate bar silently jumped from 20 lessons to 100High

certificate_service.dart:139 still reads launchScope = 20 with the comment "the launch course is lessons 001–020". But _coreNumber() now returns the topic number for TASILLA IDs, so topics 1–20 match all 100 core lessons.

The gate now requires: 100 completed core lessons, 20 teacher-approved speaking submissions and 20 teacher-approved writing submissions. The roadmap still says the MVP "honestly ships at the lower number the 20 lessons allow" and lists raising the bar to 10 speaking + 10 writing as future Phase 3 work.

The new bar is arguably the right one — it is the requirement getting there by accident, through a constant whose meaning changed underneath it, that is the risk.

FixDecide the intended bar, then make it explicit. If 100 lessons is right, rename the constant and update the comment, the roadmap and the certification standard together.
The final exam exists as content but is not part of the gateHigh

A1-EXAM.json ships in the new content. But evaluate() builds five criteria — core lessons, listening, reading, speaking, writing — and none of them is the exam. On the database side, the ≥ 0.75 check on certificates.final_exam_score was removed by the Piece 5 migration and the column left nullable.

The project's own definition of done, in mvp_spec.md §7, reads: "…and the exam is passed." As it stands a certificate can issue without one.

FixAdd an exam criterion to evaluate() and restore the DB constraint — the statements are already written and commented at the foot of mvp_piece5_certificate_gate.sql.
The base schema cannot be rebuilt from the repoHigh

supabase/migrations/ and supabase/seed.sql were deleted from disk. What survives is two loose SQL files in docs/ covering submissions and the certificate gate. The schema doc names tasilla_supabase_schema_v2.sql as the origin of the five base tables — that file exists nowhere in the project, and the live database reports only one tracked migration.

The production database is fine. Reproducing it — a staging copy, a rebuild, a second environment — currently is not possible from source.

FixRestore supabase/ from git, then dump the live schema and reconcile, so the checked-in migrations describe what actually exists.
The live database has never held a rowMedium

All 7 tables report 0 rows. No students provisioned, no submissions, no certificates. The roadmap's second Phase 0 item — "run the loop end-to-end on real data" — has not started, and every claim about the review-and-issue loop is therefore untested against production.

Suggested order of work

Restore first, then verify, then decide. The uncommitted work is valuable and currently unprotected.

  1. Protect the new work before touching anything else 149 JSON lessons, the verification page and the home-screen rebuild exist in exactly one place: this working tree, uncommitted. Commit them on a branch now.
  2. Restore the 79 deletions git checkout -- web/ test/ supabase/ tool/ scripts/ macos/ windows/ linux/. If some were deliberate — dropping macOS and Windows targets is a reasonable call — delete them in a commit that says so, rather than leaving them as working-tree noise.
  3. Run flutter analyze and the restored tests The first honest signal on whether the content swap actually holds. Expect ID-scheme failures; they are the change list.
  4. Fix the audio 40 files. Until this is done, listening cannot be scored honestly, and listening is a quarter of the certificate.
  5. Decide the certificate bar deliberately 100 lessons + 20 speaking + 20 writing, or something lower. Then align the constant, its comment, the roadmap and the certification standard — and add the final exam to the gate.
  6. Run the loop once, on real data One student, one teacher, all the way to a resolving verify link. This is the only thing that turns the definition of done from a paragraph into a fact.
